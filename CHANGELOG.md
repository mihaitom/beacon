# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Added a setting for which lyrics providers Beacon may ask. Lyrics stored with the song file itself are always tried first and never leave your server; the three internet providers (lrclib.net, NetEase, SimpMusic) are all on by default and can be switched off individually, or all of them at once, if you'd rather a song's title, artist, album and duration never be sent anywhere. Turning a provider back on takes effect right away, including for songs that had already come up empty
- Added account settings that follow the person rather than the device: the language, the personalized-recommendations toggle, the lyrics providers above and how many songs Autoplay adds per top-up. In the Docker/web version they are kept with your account on the Beacon server, so every device signed in to that instance (a desktop browser, a phone, the phone remote) picks up a change at its next login instead of each one keeping its own answer. The desktop app carries its own Beacon inside the installation, so there the four are remembered per account on that machine and don't travel to another computer. Either way, settings that are genuinely about one device (audio quality, the saved queue, cached artwork) deliberately stay put
- Local playback now buffers more ahead of time and rides out a brief loss of connection, such as a dead spot on a cellular connection, instead of stopping outright. It quietly retries the same track from where it left off, so a short gap often isn't even noticed. The seek bar shows how far ahead the current track is actually buffered as a lighter band beyond the played position, on desktop and mobile alike. Casting to a speaker was already unaffected by this kind of gap and is unchanged
- Added a "Discover stations" search to the Radio page, backed by the free Radio Browser directory. Search by name, filter by country (remembered for next time) and sort by most-voted or most-played, then either try a station straight away without saving it, or add it to your own list with one click, instead of typing in a stream URL by hand - each result also shows its location, language, audio format, popularity and whether it was reachable at its last check. Adding your own station by URL still works exactly as before
- Radio stations that broadcast a "now playing" tag show the current artist and track under the station name in the player bar and the Now Playing screen, and on the lock screen/media widget alongside the other playback controls - for local playback as well as while casting. Not every station sends this, in which case only the station name shows, same as before
- Casting an internet radio station now routes through Beacon's own backend by default, so a station is fetched only once no matter how many devices are casting it at the same time, instead of once per device. A new "Send radio straight to the device" setting under Playback (off by default) opts back into the previous behavior, for anyone who'd rather playback survive a restart of the Beacon server than get the fewer connections
- While playing an internet radio station, the seek bar now shows "Buffering…" instead of a live time that would otherwise sit frozen or jump around - while casting to a Sonos, Chromecast or DLNA speaker/TV that's still filling its own startup buffer, and here on this device too whenever a dropped connection needs a moment to reconnect

### Changed

- On Home, clicking the artwork of whatever is playing opens the Now Playing screen, the same shortcut the player bar's artwork already offers. When nothing is playing and Home is showing your most recent album instead, clicking it still starts that album, as before
- Settings that stay on a device are now kept separately per account. Two accounts sharing one computer or browser no longer see each other's audio quality, saved queue, cached library or dismissed update notice - each starts from its own. Whatever is set today is carried over to the account that's logged in the first time you run this version
- On the phone remote, an action now waits until Beacon has actually carried it out. The action sheet keeps its spinner and stays disabled until then rather than closing immediately, and a short message appears if something didn't get through. Previously a tap that hadn't landed yet looked exactly like one that had, which made it easy to add the same song to the queue twice
- The log level under Settings' Advanced section is now only offered to accounts that are also allowed to trigger a library scan, the same rule the scan button itself already followed
- While casting to an AirPlay device, the song position Beacon works with now follows how much of the song it has actually handed over, instead of assuming the same fixed delay for every track. It stays an approximation either way, since AirPlay speakers never report where they are in a song, unlike Sonos, Chromecast and DLNA speakers, which do and which Beacon goes by
- The cast panel's "Rescan" button now shows a spinner and stays unavailable until the search for speakers has finished, in place of the separate progress bar it used to show. The phone's own device sheet gained the same button, which it never had. And the first search after signing in, which takes a few seconds, now says so instead of showing "No devices found" until it's done
- A radio station's logo is now picked by what the image file actually measures rather than by what the station's page claims about it, and Beacon keeps looking for a larger one when the first it finds is too small for where it's about to be shown. A station whose logo only came back as a 32px browser icon now shows a sharp one behind the Now Playing artwork wherever the station's site offers a bigger version
- Various small UI sizing/spacing tweaks (the Albums grid now spaces its covers the same as the album shelves everywhere else, instead of slightly tighter)
- While playing an internet radio station, the seek bar now shows how long it's been running instead of a disabled progress bar with no real position or length to show
- Cover art in library grids and lists, artist photos, and radio station logos on the Radio page are now fetched in combined batches - one request per screen instead of one per image - so a large view fills in far fewer round trips, and a self-hosted deployment sitting behind a security proxy produces far less request traffic to look suspicious in the first place (same motivation as the ban fix below). Artwork that has already been fetched is kept - in the open app, on your Beacon server, and in the browser's own storage - so moving back and forth between views shows it instantly instead of loading it again, a second device is answered without going back to the music server at all, and in the browser version the artwork you have already seen is still there after a reload or the next time you open the page. A cover you replace on the music server still appears right away rather than waiting for anything to expire, because Beacon now tells covers apart by which picture they actually are - on Jellyfin and Plex too, where a replaced image used to look identical to the old one from the outside. Artist photos in particular used to be fetched from wherever the music server pointed to, once per artist and once per view; they now come the same way as everything else, which is also what stops them from being re-downloaded on every visit. Artwork is also requested at four fixed resolutions instead of at each place's exact pixel size, so the same cover is stored once for a whole group of views rather than separately for each, which both makes the caches go much further and leaves the music server far less scaling to do - small thumbnails come out sharper on high-resolution displays as a side effect. In the Docker version, how much memory the server may use for this is adjustable with `COVER_CACHE_MB` (see the README), 128 MB by default
- Beacon now stops its background checks (each speaker's volume, the device list, a radio station's "now playing" tag) while the window is hidden, and pauses them entirely for a while when a security proxy in front of a self-hosted Beacon starts refusing requests, waiting longer each time it is refused again. Anything you actually click still goes through and still reports what happened. Previously those checks carried on regardless, which could achieve nothing but keep a block alive that would otherwise have expired

### Fixed

- Fixed picking a speaker another Beacon session is using going wrong in three separate ways. Switching to one stopped the speaker you were already listening on and dropped the music back to this device before you had even answered the "take it over?" question, and answering it then did nothing at all. "Take over" on a speaker you wanted to add stopped every other speaker you had playing. And picking one from the phone remote did nothing, while a confirmation nobody was looking at appeared over on the desktop instead. The speaker you are on now keeps playing until you answer, confirming carries out the whole switch, taking a speaker over adds it to the ones you are already on, and the phone takes it over directly
- Fixed picking a speaker while playback is paused making a sound. Adding a second speaker, or switching to one, while already casting started the music playing outright; and picking a first one, which did correctly stay paused (see 0.1.4), still made the speaker play a moment of the song before being stopped again. A speaker picked while paused is now simply reserved: it is yours, it holds the song and where you are in it, and it stays silent until you press play. This applies wherever the choice is made - the desktop panel, the phone's sheet and the phone remote. Radio is the one exception and still makes that brief sound, because whether a station plays on a given speaker at all is only found out by trying it
- Fixed moving a cast from one speaker to another. Switching between two Sonos speakers interrupted a third Sonos that was playing on its own and had nothing to do with the switch; the switch itself locked up the play/pause and seek controls for several seconds while it looked for the speaker on the network; and afterwards the queue stalled, with the song finishing normally and then the speaker staying silent for roughly the length of another track before the next one started on its own. Only speakers actually grouped behind the one being switched off are restarted now, the speaker is looked up the same fast way as everywhere else in Beacon, and position tracking is handed over to the speaker that keeps playing
- Fixed a speaker that refuses to stop being left listed as still playing with nothing said about it, so the panel kept showing it as a target that Beacon no longer had. The failure is now reported and the speaker drops out of the list
- Fixed both device pickers showing a set of speakers that was not real. The phone's sheet kept whatever it showed when it opened and applied that as your choice on "Done", even after the speakers had changed underneath it, and the desktop panel's tick marks briefly flicked back to the speaker just switched away from right after applying a change. "Done" on the phone now also reports a failure rather than appearing to do nothing, and stays open so the selection can be tried again
- Fixed casting to some Chromecast devices (e.g. a Google TV) staying completely silent, with no error shown anywhere. Those devices can keep their own app running instead of switching to the one that actually plays what's sent to it, and were accepting the request without ever starting playback. Beacon now explicitly switches the device into playback mode first
- Fixed a failed cast reporting the speaker's raw technical fault ("UPnP Error 800 received: from 10.2.2.112") as the whole error message. The cast panel now says which speaker it was and what went wrong - it refused what it was sent, it was busy, or it could not be reached - with the original text kept underneath in smaller type
- Fixed the stream-info panel (in the cast device picker) claiming a cast radio station was being transcoded to MP3, regardless of the audio quality chosen for casting. Radio is never transcoded by Beacon - it hands the station's own stream straight to the target device - so the panel now shows nothing while radio plays, same as it already did during local playback
- Fixed an internet radio station going silent on a speaker while you were told the wrong thing about why. A station whose address no longer serves refuses every request, and what you saw was the speaker reporting access denied and then, once Beacon tried converting the stream, a corrupt file - two complaints about a speaker that was working fine. Separately, a speaker refusing a station it cannot decode, or one published over https on the station's own host (which some speakers won't fetch at all, even for plain MP3), simply went quiet with nothing said. Beacon now checks the station first and says plainly when the station itself refused, without bothering the speaker at all; and when it is the speaker that turns the station down, it falls back to converting the stream itself, whatever the reason. The cast panel's stream info shows that this happened and why, and if even that doesn't work you get a message naming the speaker instead of silence
- Fixed casting an internet radio station in a format other than MP3, AAC in particular, failing outright with an unsupported-format error on Sonos. Beacon announced every station as MP3 regardless of what it really sends. It now asks the station itself what it sends rather than guessing from the address's file ending - a station whose address ends in .aac is routinely HE-AAC, and being told the wrong one is enough for a speaker to refuse it - and every speaker that joins a station already playing is told the same thing as the first
- Fixed a cast failing outright, or a station staying silent on this device, for radio stations published as a playlist file (a .m3u or .pls address, which names where the audio is rather than being it). Beacon now looks inside one and plays what it points at, for casting and local playback alike. This affects stations added by hand as well as ones found through "Discover stations", since the directory's own resolved address is sometimes the playlist too
- Fixed pressing play doing nothing for an internet radio station that was showing but not yet loaded - specifically, right after restarting Beacon while a station was selected but paused. Playing a song from the library in the same situation already worked
- Fixed artwork staying blank, album covers and radio station logos alike, from three separate causes: a first attempt that didn't get through (the server briefly unreachable, a timeout, a dropped connection) was never tried again; the player bar's very first cover in the installed app was drawn before the connection to your server was ready, and nothing retried it, not even on the next track; and one malformed icon link on a station's own page made the whole logo lookup fail instead of being skipped, reaching the app as a misleading connection error rather than as the fault it was. Artwork is now retried a few times, waiting longer between tries, and again as soon as the connection is there. Artwork the server says does not exist is still not retried
- Fixed a radio station's logo staying blank in the player bar and on the Home screen, sometimes for days on end and through restarts, while the very same logo showed fine on the Now Playing screen. The logo is cached in the browser for a week, and the cached copy was missing a marker saying it may only be reused for the kind of request it was fetched for. Once a copy without that marker was stored, the app was refused its own image from its own cache, without ever asking the server again - which is why restarting Beacon, or reloading, never helped. Any copy already stored this way is stepped around automatically, so no cache needs clearing by hand
- Fixed a radio station's logo being cropped on the Now Playing screen. Station logos are whatever shape the station made them, often a wide banner, and filling a square with one cut the name off it. Album art is unaffected - it is square, and still fills its frame
- Fixed the Home screen's hero card ignoring a playing internet radio station: it showed whatever album had played last instead of the station's own logo, and pressing play on it started that album rather than resuming the station
- Fixed Beacon being able to get a self-hosted instance's own address banned by the security software guarding it, from two different bursts of failed requests. The live-update connection (used for playback status and the cast visualizer) retried every couple of seconds, indefinitely and without slowing down, whenever it couldn't stay connected - frequent enough on mobile data or a flaky WiFi hop to look like an attack. And the Radio page asked for every station's logo separately, re-asking about every station that had none on every single view, forever, because the "there isn't one" answer was never allowed to be remembered - so simply opening the page produced a burst that looks, to that kind of software, like something scanning the server. The connection now waits progressively longer between attempts and pauses entirely while the device is offline, and the Radio page asks for a whole screen of logos at once and remembers which stations have none. A block was worth avoiding for more than these two: while one is in effect nothing gets through at all, which is what could stop the music mid-song on a speaker
- Fixed the personalized recommendations toggle missing from Settings altogether for accounts that aren't allowed to trigger a library scan, such as a regular non-admin Navidrome account. It applies to every account and every server, and is now shown to all of them
- Fixed the filter box on Songs, Albums, Artists, Genres and Playlists not finding a title, artist or album when the typed text left out an accent the source used, such as searching "revolution" for a song actually named "La Rèvolution". Works the other way round too, and regardless of which specific accent is involved
- Fixed a song that Autoplay had just added to the queue occasionally disappearing again and getting replaced by a different one a moment later, when two devices were connected to the same cast session and both topped the queue up around the same time. Only the first addition is kept now

## [1.0.1] - 2026-08-28

### Changed

- The two Discover shelves on Home fill in faster. The suggestions and the artist list are now looked up at the same time instead of one after the other, and the albums behind the matching artists are fetched together rather than one request at a time, only as many as the shelf actually shows
- Pressing previous now goes back to the previous song for the first five seconds of a track instead of only the first three, so a quick correction after a track change lands on the song you meant rather than restarting the one that just started. Later than that it still restarts the current song, as before

### Fixed

- Fixed Autoplay reading as off on one device while the queue kept filling up anyway. While casting it is a setting of the listening session, like shuffle and repeat, so every device now shows the same state and switching it off takes effect immediately instead of at the next track. Previously each device only remembered its own setting and the server kept topping the queue up from whichever one had last started playback
- Fixed the "New artists to explore" shelf on Home showing nothing at all while it loads, then appearing out of nowhere below a page that had already settled. It now shows the same placeholder cards as the shelves above it from the start
- Fixed music stopping the moment the screen locked, or the browser went to the background, in the mobile web player on a phone or tablet. Playback now carries on, with the track and its controls on the lock screen. What it costs on those devices: the audio visualizer is no longer offered for playback coming out of the phone itself, ReplayGain there applies to casting only, and the volume slider for local playback is gone, since a phone browser never let it do anything anyway and the device's own volume buttons are what changes that level. All three are unchanged while casting, and on the desktop app and in desktop browsers
- Fixed playback staying completely silent in the mobile web player on iPhone and iPad: pressing play started the track, showed it running and moved the progress bar, but no sound came out until the Now Playing screen happened to be opened. Playing from a desktop browser or the installed app was never affected
- Fixed the service icons next to an artist's external links (Spotify, Apple Music, TIDAL, YouTube, Deezer, Discogs, MusicBrainz) not showing up at all in the installed desktop app, leaving the row of links without any of their logos - they only ever appeared when running from source or in the Docker build
- Fixed quitting the desktop app while casting leaving it, and the speaker, playing for the rest of the track instead of stopping right away

## [1.0.0] - 2026-08-27

### Added

- Added the library rescan to Jellyfin and Plex servers, which previously only worked with Navidrome. It stays hidden for accounts that aren't allowed to run one, same as everywhere else, and since neither server counts the tracks it has processed, the button shows how far along the scan is as a percentage instead
- Added the shuffle button to the "New artists to explore" shelf as well, so a fresh set of suggestions can be asked for from either shelf rather than only from the albums one above it. Each button changes only its own shelf, which shows placeholders while it waits instead of briefly disappearing

- Added support for the lyrics stored with the file itself on Jellyfin and Plex servers - the same ones Navidrome already provided. Those describe the exact recording being played, so they are used ahead of the internet lookup, which still covers everything without them. Jellyfin reads them from the track's tags or from an .lrc file next to it; Plex only from the .lrc, so a library that keeps its lyrics in the tags will keep getting them from the internet lookup there
- Added keyboard shortcuts to the player: Space (or K) plays and pauses, the left/right arrows seek five seconds, Ctrl (Cmd on a Mac) with them skips tracks, the up/down arrows change the volume, M mutes, S and R switch shuffle and repeat, F favorites what's playing, Q opens the queue, and the number keys jump into the track. Press ? for the full list, which is also reachable from Settings. They stay out of the way while you're typing or a dialog is open, and while casting to a single speaker the volume keys change that speaker's volume, just like the slider in the player bar does
- Added drag-and-drop reordering of the songs in your own playlists, the same way the queue already worked - the song moves right away and is put back with a message if the server refuses the change. Sorting a playlist by a column temporarily takes the drag away, since the rows are then no longer in the playlist's own order; clicking that column a third time goes back to it
- Added track title, artist, album and cover art to what AirPlay devices show while casting - previously an Apple TV or HomePod displayed nothing at all, since the details were never sent and the artwork is stripped from the audio stream before it leaves the server
- Added an audio quality setting, separately for this device's own playback and for casting. Both are upper limits rather than fixed choices: anything already below what you set is played untouched, so picking "MP3 320" won't re-encode a 128kbps file into a bigger one. Above it, the music is converted as it plays - which cuts how much data gets pulled over a mobile connection, and also makes files playable that the browser can't open by itself (ALAC, APE and the like). While casting, Beacon still picks the best format each speaker will take on its own and only stops short of your limit. Both settings are stored per device, so a phone and a desktop can be set differently, and a change takes effect from the next track onward
- Added a notification when a speaker you're casting to stops on its own: instead of the music just ending in silence, a message says which device dropped out and offers a Resume button that picks playback back up from where it left off. It shows up on the desktop, in the mobile web player and on the phone remote, and covers AirPlay as well as Sonos, Chromecast and DLNA. Beacon deliberately doesn't restart playback by itself, since a speaker being stopped on purpose and one dropping out look exactly the same from its side
- Added Autoplay - once the queue is down to its last song or so, similar songs get added automatically so playback never just runs dry. Off by default; toggle it from the icon next to Queue in the player bar, and set how many songs get added per top-up in Settings. Works the same for local playback and casting, and keeps topping the queue up on its own server-side even if nothing's around to do it locally (e.g. a phone's screen is locked)
- Added Song Radio, Artist Radio, and Autoplay support for Plex (needs an active Plex Pass on the account) - previously Navidrome/Subsonic and Jellyfin only
- Added OS media key support - play/pause/previous/next now work from the keyboard's media keys, the lock screen on Windows/macOS, and the media widget on GNOME/KDE, showing the current song's title/artist/artwork
- Added an A-Z jump bar to the Albums and Artists views, and to any song list sorted alphabetically by title that's long enough for it to be worth it - drag or tap a letter to jump straight there instead of scrolling by hand
- Added a count to a song's right-click menu ("5 songs selected") when several are selected, making it clear the actions below apply to the whole selection - Play now replaces the queue with just the selected songs and starts the first one instead of playing from wherever was clicked through the full list, and Song Radio drops out of the menu since it can't act on more than one song at a time
- Added a "Show all"/"Show less" toggle to an artist page's Most Played list once there are more songs by them than the top 10 shown by default - the section title switches to "All songs" while expanded, and toggling back and forth after the first time is instant
- Added a play icon to the numbers in the Stats page's Top Songs/Artists/Albums/Genres lists, replacing the repeated "X plays" text next to each entry
- Added a second quick-play action to the Songs, Genre, Albums, and Artists views, alongside the already-random one: picks from what's actually been played a lot instead of the whole (or, for a genre, whole-genre) pool, so it leans toward music you already like rather than being a total shot in the dark
- Added an automatic peek at the queue whenever something lands in it without being clicked song-by-song - those quick-play actions, Play Next/Add to Queue, Song Radio, Artist Radio, and Autoplay's own top-up all trigger it. The queue opens with each track sliding in from the right one after another and scrolls to whatever's currently playing, then closes itself again after a few seconds unless the mouse actually reaches it, in which case it stays open
- Added a matching fade-out to clearing the queue - tracks disappear bottom-to-top starting from wherever you've actually scrolled to, instead of all at once
- Added a "Stop all" action to the device picker in the mobile web UI and on the phone remote, matching the one already on desktop - previously the only way to back out of casting there was picking "This device", which also switches playback to it right away
- Added a Song Radio button to the Home view's hero card, next to Keep listening - starts a mix built around whatever song is currently playing there. Hidden when the card is showing a recently played album or an internet radio station instead, since neither gives a single song to build a mix around
- Added a way to save the current queue as a new playlist, right from the queue drawer
- Added a confirmation prompt before deleting a playlist
- Added a small stream info section to the device picker, for whatever is currently playing the music - whether the track is being converted, what it is being turned into (including the sample rate and bit depth when those had to be reduced), the source file's own format, sample rate and bit depth, and, while casting, why it is being converted and how the connection to the speaker is doing
- Added mouse wheel control to the volume sliders in the player bar and in the casting device list - scrolling over one moves it in 5% steps, and changes whatever that slider is currently for, this device's own volume or the speaker being cast to

A button appears while they are held that way and follows the song again when pressed, and the fullscreen view no longer shows a scrollbar beside them

- Changed the queue and lyrics panels to sit side by side when both are open, instead of the second one covering the first exactly - closing it used to reveal a panel underneath that there was no reason to expect
- Changed the Favorites view's artists and albums to scrollable rows with arrows, like the Home view's shelves

- Changed notifications to stop counting down while the mouse is over them, and to stay up longer when they're asking you to decide something rather than just telling you what happened
- Changed how Beacon talks to the music server so connections are held open and reused properly, instead of most of them being torn down and rebuilt between requests: browsing and scrolling through a large library is noticeably quicker, and a burst of requests no longer disrupts anything currently casting
- Changed the device picker so the ticked devices are simply where you want playback to go, applied in one step: unticking one no longer stops it on the spot, so switching from one speaker to another no longer drops back to this device's own speakers in between. The button now reads "Apply" and only appears when there is actually something to change. "This device" is now listed at the top like any other target, marked while it is the one playing and clickable to bring the music back to it, and the panel is titled "Playing on" rather than "Casting"
- Changed an artist page's albums from a wrapping grid to a scrollable row (like the Home view's shelves), sorted newest-first by default with a toggle to flip it to oldest-first
- Changed the Home view's two "discover" shelves for more headroom and a clearer distinction between them - the library-based one now shows up to 20 albums instead of 15 on wide screens, and both got clearer titles ("Discover in your library" / "New artists to explore") so it's obvious which is drawn from albums you already own and which is brand-new artist suggestions
- Changed song lists (genres, favorites, search results, playlists, album tracklists) to load more as you scroll instead of paging through numbered pages, matching how the Songs library view already worked
- Changed selecting multiple songs to no longer show a floating action bar - Play Next/Add to Queue/Add to Playlist for the whole selection already live in a selected song's right-click menu, so the bar was just duplicating them; press Escape to clear a selection instead of its old close button
- Changed where an artist page's external links (Spotify, Apple Music, TIDAL, YouTube, Deezer, Discogs, MusicBrainz) show up - they sit next to the Artist Radio button now instead of crowding the top-right corner alongside the rating stars and favorite heart
- Changed cover art to load a few at a time and only once scrolling actually comes to rest on it, to stop loading again the moment it scrolls back out of view, and to be cached by the browser afterward, instead of every cover on a page being requested at once and every started download running to the end regardless - large grids and lists load noticeably faster, flicking through a huge list no longer fetches a cover for every song it races past on the way, and coming back to a list no longer re-fetches art that was already shown
- Changed the seek bar to stop stretching past 600px wide on very wide monitors
- Changed the fullscreen visualizer's cast mode to only analyze the audio while somebody actually has it open, instead of doing that work for every cast whether or not anyone was watching - casting is noticeably lighter on the server, and opening the visualizer part-way through a song picks the music up where it is. Also now available while casting to AirPlay, which couldn't show it at all before
- Changed a Sonos speaker's volume and mute to update in Beacon right away when changed from elsewhere (the Sonos app, another Beacon session), instead of up to 4 seconds later - Chromecast and DLNA devices still poll for now
- Changed the blurred artwork backdrop behind the Home view's hero card and every album/artist/genre/playlist header to crossfade when it changes, instead of snapping over to the new artwork the moment it loads. All of them now fade at the same speed as the Now Playing view's own backdrop, which already worked this way
- Various small UI sizing/spacing tweaks based on actually using it
- Changed artist cards to the same size as album cards, so the two line up where both appear (the Favorites view, any mixed grid) instead of the artist ones sitting noticeably larger
- Changed the Playlists view's rows to a bigger cover with the play button on it (shown on hover) instead of a small cover next to a separate play button off to the side
- Changed the "Filter" field on the Songs, Artists, Albums, Genres, and Playlists views (desktop and mobile web) to say "Search" instead, with a matching magnifying-glass icon - it now actually behaves like one (see the matching Fixed entry below)

### Fixed

- Fixed the Linux app having no icon at all in launchers, taskbars and app menus: it was packaged in a single 1024x1024 size, which the desktop icon standard doesn't define and no launcher looks in. It now ships in the usual sizes from 16 up to 512
- Fixed how lyrics are matched to a song, which regularly settled on a different recording's words: how long the song actually runs is now part of the decision (an extended version's lyrics on a radio edit start late and drift further apart as it plays), a result credited to a different artist is passed over however closely the title reads, and a "lyric sheet" that turns out to be nothing but songwriter credits is skipped in favour of the next result - or none at all, when that is the truth
- Fixed stray characters turning up inside lyrics: a control character left over from how they are stored inside a file, which every server passed along, and raw timestamps appearing as though they were part of the words whenever they carried a trailing marker

- Fixed lyrics staying on whatever was found on the internet even after the song's own file had gained some - a result found at a provider was cached and never revisited, so tagging a library you had already listened to changed nothing on screen. Lyrics coming from the file itself are still cached for good; a provider's copy is now re-checked against the file from time to time, in the background and without the panel flickering

- Fixed an internet radio station losing its logo in the player bar and on Now Playing while it keeps playing - the station was rebuilt from the casting session's own state, which knows only its name and stream URL, so the homepage the logo is fetched from went missing and the generic radio icon took over. - Fixed the queue drawer closing itself on schedule even when something new had landed in it moments before (Autoplay topping up the queue right after a peek opened it, say) - it now stays open the full peek duration from whatever most recently showed up in it, instead of closing partway through a reveal it hadn't finished showing yet
- Fixed the app automatically resuming audio playback after being fully restarted while a song was playing, instead of waiting for you to press play yourself - the queue and position still pick up right where you left off either way, and a plain reload (not a full restart) still resumes playing too, same as before
- Fixed the search field on the Songs, Artists, Albums, Genres, and Playlists views (desktop and mobile web) not finding a match when the search words were split across different fields (e.g. "Michael Jackson Bad" needing to be typed as either "Michael Jackson" or "Bad" alone to find the song) - it now matches each word independently, the same way the search in the top bar already did
- Fixed the app going unresponsive for up to about 1.5 seconds the first time it scans for devices after starting, which also held up the audio being sent to a speaker for that moment if something was already casting - opening the device picker mid-playback was enough to trigger it
- Fixed a speaker that briefly lost its connection starting the current song over from the beginning instead of picking it up where it was, which also left the progress bar, synced lyrics and the visualizer jumping around afterwards - bad enough that the only way out was reloading the app and skipping the song
- Fixed casting stopping roughly half an hour into a long track - a DJ set, a live recording, a long mix - whenever no Beacon window was open anywhere. The music simply ended mid-track and the speaker went quiet, as if the device had dropped out
- Fixed a speaker being stopped out of the blue about half an hour after a session was last used, even when something else had started playing on it in the meantime - another device in the house, another person, or a second copy of Beacon. - Fixed the app locking up for a moment while the seek bar's waveform was being prepared for a very long track, such as a DJ mix or a live set: with playback going to a speaker, the pause was long enough to interrupt the audio being sent to it

- Fixed picking a second device while already casting silently dropping the first one - it kept playing until the end of the current track and then went quiet, with only the newly picked device carrying on
- Fixed the displayed position while casting going wrong in a whole family of ways, taking the synced lyrics and the audio visualizer with it since both follow it: it could flicker for the rest of a track, briefly run ahead of what was audible after resuming, snap back toward 0:00 after a restart or seek, or drift further out with every pause until it was minutes off. - Fixed casting mishandling the end of a track in two opposite ways: it could advance to the next song a few seconds early and cut off the tail of the current one, or get stuck at the end and never move on at all, with the position quietly snapping back to 0:00 instead. Both came from a cast device being paused, resumed or reporting itself idle at exactly the wrong moment
- Fixed a cast session occasionally getting stuck looping near 0:00 with no audio, indefinitely, particularly on long tracks or compilation albums - streaming had no pacing, so formats that don't need re-encoding could reach a cast device many times faster than actual playback, leaving its connection sitting idle for long stretches once everything was already sent and prone to being dropped there; streaming now stays paced only a little ahead of real playback instead. A drop that still happens now also recovers within seconds instead of the display getting stuck resyncing against the disconnected device's "nothing playing" reading as an endless string of rewinds to the start
- Fixed joining an unreachable device to an existing cast session leaving it stuck marked as in-use for everyone else, even though nothing was actually playing on it
- Fixed casting to several devices at once silently appearing to succeed, with no error shown and every device staying marked in-use, when none of them actually managed to start playing
- Fixed the Electron Remote Control pairing occasionally reporting the app as unreachable right after a quick reconnect (a brief network blip, for example), even though it was already back and listening again
- Fixed the seek bar's waveform occasionally overflowing into neighboring player bar elements at narrower window widths instead of shrinking to fit
- Fixed a ReplayGain-adjusted track not playing at all while casting if its format didn't need re-encoding (MP3, FLAC, AAC, Ogg Vorbis) - the volume adjustment and that format's fast, lossless pass-through can't be combined; such a track now gets a quick re-encode instead so ReplayGain still applies
- Fixed a deleted playlist reappearing in the Playlists view, sometimes for up to an hour afterward - deleting it updated what was on screen right away, but not the on-device cache checked first on the next visit
- Fixed a rare inconsistency after force-taking over a device from another session: if that session's own attempt to (re)start playback on the same device failed at almost the same moment, its failure cleanup could undo the takeover, leaving both sessions disagreeing about who actually has the device until something else refreshed it
- Fixed the Songs, Albums, and Artists library views getting progressively slower and less responsive the further you scrolled through a large library - every row/card stayed mounted after loading more instead of only the ones actually on screen
- Fixed a song's right-click menu not closing when another song's was opened - each could be opened independently, leaving several stacked on top of each other at once
- Fixed clearing the queue while casting getting silently undone a few seconds later, with every song reappearing - the clear never made it past this device to the cast session itself

### Added

- Added live sync of the queue, shuffle, and repeat state across every device controlling the same cast session - reordering, adding, or removing a song, or toggling shuffle/repeat, on one device now shows up on every other connected device too (previously only which song was playing and its position stayed in sync; the queue itself was independent per device)
- Added playlist artwork to the Electron Remote Control PWA's playlist list - it only ever showed a plain title/song count before
- Added a fullscreen toggle to the Now Playing view (top right) - hides the rest of the app's chrome around it for a more immersive view; a lyrics button appears alongside it while fullscreen is active, since the usual one (in the player bar) is part of that now-hidden chrome
- Added a flip animation for lyrics on portrait/narrow monitors - the artwork now turns over to reveal lyrics on its back instead of squeezing both side by side or stacking them; also brings lyrics to the mobile web UI for the first time, via a new toolbar button, using the same flip since phones are always portrait too
- Added a Trace log level, one step past Debug - Debug now covers Beacon's own backend code only, Trace also turns on the third-party libraries underneath it (Sonos/AirPlay, HTTP clients) for full SOAP/HTTP-level detail when actually troubleshooting one of those. A new `LOG_LEVEL` environment variable sets the starting level the same way the Settings dropdown does, for a deployment that never comes up far enough to reach Settings
- Added links to Spotify, Apple Music, TIDAL, YouTube, Deezer, Discogs, and MusicBrainz on artist pages, and on the Home "New to explore" shelf - the shelf previously only linked out to Deezer itself (or MusicBrainz as a fallback), and an artist page for someone already in your library had no external links at all

- Changed the lyrics view's "pick a different match" list on mobile from a dropdown menu to a full-width sheet - easier to hit and to read than a small floating panel anchored to a toolbar button
- Various small UI sizing/spacing tweaks (mobile web UI, Now Playing on wide monitors, lyrics on mobile) based on actually using it

### Fixed

- Fixed the app log file (see 0.1.3) tagging every line from the backend as an error, even completely normal status messages - the backend logs everything to the same output stream regardless of severity, same as most command-line programs, and the log file was mistaking that stream choice for severity
- Fixed queue changes made while casting (reordering, adding, removing, shuffling) not being followed by auto-advance once nothing was around to manually skip to the next song - the cast target kept auto-advancing through whatever queue order was active when the current song started, ignoring anything changed since
- Fixed picking a cast target while local playback was paused starting playback on that device right away instead of staying paused
- Fixed the Previous/Next buttons resuming playback immediately even if it was paused - navigating now stays paused, matching what selecting a cast target already did
- Fixed the "now playing" display occasionally showing a different song than what was actually playing when two devices controlled the same cast session and both changed something around the same time
- Fixed shuffle not actually shuffling the first song when playing a whole playlist/album from the top - it always started on track 1 in its original order, with shuffle only kicking in from the second song onward
- Fixed the mobile web view carrying over a tab's scroll position into whichever tab you switched to next, instead of each tab keeping (and restoring) its own
- Fixed the Docker/web deployment's audio stream to cast devices being vulnerable to nginx buffering it all at once instead of forwarding it continuously in real time - could turn a brief network hiccup mid-song into a multi-minute stall stuck at 0:00 instead of recovering

- Fixed pressing Play again after a cast session's queue finished playing (no repeat, last song ended): position stayed frozen at 0:00 and the audio visualizer/synced lyrics never got going, since resuming just asked the already-finished stream to continue instead of properly restarting it - the same bug fixed for local playback in 0.1.1, which never covered casting
