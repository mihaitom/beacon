# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- With the log level set to Debug or Trace, the fullscreen visualizer now shows what it is working from while casting: the moment it is drawing and the moment playback is actually at, with the difference between them highlighted once it grows large enough to hear. It is the difference between suspecting the bars are out of step with the speaker and being able to see it. Invisible at the normal log level
- The Jellyfin Quick Connect code can now be copied with a button beside it, rather than read off the screen and typed out. The device you approve it on is often a second window on the same computer, where retyping six characters is pure friction
- Added a setting for which lyrics providers Beacon may ask. Lyrics stored with the song file itself are always tried first and never leave your server; the three internet providers (lrclib.net, NetEase, SimpMusic) are all on by default and can be switched off individually, or all of them at once, if you'd rather a song's title, artist, album and duration never be sent anywhere. Turning a provider back on takes effect right away, including for songs that had already come up empty
- Added account settings that follow the person rather than the device: the language, the personalized-recommendations toggle, the lyrics providers above and whether cast radio goes straight to the device. In the Docker/web version they are kept with your account on the Beacon server, so every device signed in to that instance (a desktop browser, a phone, the phone remote) picks up a change at its next login instead of each one keeping its own answer. The desktop app carries its own Beacon inside the installation, so there they are remembered per account on that machine and don't travel to another computer. Either way, settings that are genuinely about one device (audio quality, the saved queue, cached artwork) deliberately stay put
- Local playback now buffers more ahead of time and rides out a brief loss of connection, such as a dead spot on a cellular connection, instead of stopping outright. It quietly retries the same track from where it left off, so a short gap often isn't even noticed. The seek bar shows how far ahead the current track is actually buffered as a lighter band beyond the played position, on desktop and mobile alike. Casting to a speaker was already unaffected by this kind of gap and is unchanged
- Added a "Discover stations" search to the Radio page, backed by the free Radio Browser directory. Search by name, filter by country (remembered for next time) and sort by most-played (the default) or most-voted, then either try a station straight away without saving it, or add it to your own list with one click, instead of typing in a stream URL by hand. Each result is a card showing the station's logo, where it is, what it broadcasts and how popular it is, plus whether it was reachable at its last check; tap the logo to listen, tap the plus to keep it. Works on the phone as well as the desktop, where it fills the screen and puts the popularity figures under the name so nothing has to be scrolled sideways. Adding a station by hand, by typing its address, is still there on the desktop. Beacon also reports back to the directory each time you actually listen to a station you found there, which is what its popularity ordering is built on, rather than taking that ordering without contributing to it
- Radio stations that broadcast a "now playing" tag show the current artist and track under the station name in the player bar and the Now Playing screen, on the phone and the phone remote as well as on the desktop, and on the lock screen/media widget alongside the other playback controls - for local playback as well as while casting. Not every station sends this, in which case only the station name shows, same as before
- While an internet radio station is playing, the panel that shows a song's lyrics now shows what the station has played instead, with the time each title came in. Open it the same way as lyrics: the button in the player bar, or the one on the Now Playing screen on the phone. Every station keeps its own list, so switching away and coming back finds that station's history rather than a mixed one. Stations also send things that are not songs through the same channel - a programme name, a news item, their own slogan - and those are kept and shown as plain lines rather than guessed at and thrown away, since no rule tells them apart from a song without losing real songs too. A station that repeats the same few lines on a loop, as news stations do, does not fill the list with them, and the list scrolls wherever it is shown, including on the phone. Clicking a title searches your own library for that track, so a song you just heard on the radio is one tap away from the copy you own - on the phone that goes to the phone's own library screen, already filtered, rather than the desktop search page. A list that runs past midnight is split by day, so two entries an evening apart are not both just "23:50". The list is kept by the Beacon server rather than by the app, so it carries on filling while you are casting with the app closed, and it survives a restart: start a station again tomorrow and what it played yesterday is still there
- Casting an internet radio station now routes through Beacon's own backend by default, so a station is fetched only once no matter how many devices are casting it at the same time, instead of once per device. A new "Send radio straight to the device" setting under Playback (off by default) opts back into the previous behavior, for anyone who'd rather playback survive a restart of the Beacon server than get the fewer connections
- The phone remote gained the mini player strip above the tab bar that the mobile web view already had: what is playing, with previous, play/pause and next, on every page except Now Playing itself, and a tap anywhere on it opens that page. The mobile web view's own strip gained the previous button, which it never had
- Right-clicking in the library now offers what that thing can do, not just what fits on the tile. An album can be played, queued next or at the end, added to a playlist, and links through to its artist; an artist offers Artist Radio and their whole catalogue; a playlist can be renamed or deleted straight from the overview instead of only from its own page; a radio station's edit/delete menu now opens on right-click as well as from its button; and a track row gained "Go to album" and "Go to artist", which the columns only show in some views. Only one menu is open at a time, and it goes away again on a right-click anywhere else or as soon as the page scrolls
- Settings has a new Privacy entry listing every outside service Beacon contacts, what each one is asked for, and what is sent with the request - split by whether the connection comes from your device or from your Beacon server, since only the first shows the far end your own address. Services that a setting can switch off say which setting that is
- Cover art and artist photos can now be looked at full size, filling the window. Click the artwork at the top of any album, artist, genre or playlist page, click the photo of one of the suggestions under "New artists to explore" on Home, or right-click an album or artist tile in a grid or a track in a song list and pick "Show image". A suggested artist's photo is fetched at a much larger size for this than the small card needs, with the card's own picture filling the view while that arrives, so nothing is covered by a placeholder on the way. It is fetched at a higher resolution than the browsing views ask for, so a cover stays sharp at that size, and an artist photo is shown as it actually is rather than cropped to a circle. Clicking anywhere on it, or pressing Escape, closes it again
- The desktop window gained back and forward arrows beside the Beacon name in the top bar. Until now a page you had opened from somewhere else was a dead end: open an album from an artist page and the only way back to that artist was to search for them again. Alt with the left or right arrow key does the same, as do the back and forward buttons on a mouse that has them. Each arrow greys out when there is nothing behind or ahead of the page you are on
- Right-clicking a track now offers Info, which opens everything your media server holds about it: the tags (sort name, album artist, disc, BPM, mood, comment), the audio itself (format, bitrate, sample rate, bit depth, channels, file size, path), what the library knows (plays, last played, when it was added, rating, ReplayGain) and its MusicBrainz and ISRC identifiers. Only the fields your own server actually reports are listed, so nothing shows an empty line for something it was never told. Navidrome answers with the most; the Jellyfin and Plex bridges now pass through everything those two expose for a single track rather than just what a list row needed

### Changed

- Searching now returns a page's worth of results rather than 25 of each kind. A common first name matches far more than that in any real library, and nothing said the list had been shortened - it simply looked like everything the server had. Songs get the most room, since that is the list you scan; albums and artists are a handful of tiles above it
- Search results now show matching artists and albums as scrolling rows with arrows to page through them, the same shape Home and your favourites already use, instead of a list and a grid that both grew downwards. A search for a common word can match dozens of each, and stacked up they pushed the matching songs off the screen; sideways each kind of match takes one row's worth of height however many there are. Each row has a button to open it out into a grid instead, remembered separately per row, so a search that turned up three artists and ninety albums can show those two differently. The albums on an artist's own page gained the same button
- Playing a track from the search results now plays just that track, instead of also putting every other match in the queue behind it. A search is a list of things that happen to contain the same word, not a running order - so "Moon" no longer arrives with nineteen other moons queued up after it. The same goes for tapping a song in the library on the phone, where it also matches what that row's own menu already did, and for the most-played list on Home, which is a chart rather than a running order - the play button next to its heading still starts the whole list. Play next, Add to queue and Song Radio are still there for building a queue on purpose, and albums, artists and favourites carry on playing through as before
- The heart for marking a song a favourite is gone from the song lists on the phone. There is no favourites screen there to look at afterwards, so it was an action with no visible result. Marking favourites still works on the desktop, where the list it feeds exists
- The page headings across the phone views now match. Queue, Library, Playlists, Radio and a playlist's own page each opened with the same thing spelled four different ways, so they sat at different distances from their content; they share one header row now. The search box stays in reach while the list scrolls on Library and Playlists too, which until now only Radio did
- On the phone remote, every tab now opens with its own name at the same size. Queue and Library had no heading at all, Playlists and Radio each had one at a size of its own, and Radio called itself "Internet Radio" while its tab said "Radio". Its lists and the strip above the tab bar also match each other now, and match the mobile web view: same artwork size, same two lines of text, same row height, so the two ways of using Beacon from a phone no longer look like two products
- Queue, Library, Playlists and Radio on the phone now read as one app. They had drifted into three artwork sizes, three title treatments and four different row heights, which looked like four separate designs; artwork, row height, the two lines of text and the thin line between entries are now the same across all four, and every list is one run of rows rather than a stack of rounded cards. The strip showing what is playing, above the tab bar, matches those rows too. What each list actually offers still differs, as it should - a queue row can be dragged, a station can be edited, a song can be favourited
- Adding a radio station by hand is no longer offered on the phone. It is three URL-shaped text fields, and nobody types a stream URL on a phone - Discover reaches the same result with a search and one tap. The desktop keeps it
- The two-way switches across the app (ReplayGain in Settings, Songs/Albums in the phone's library, the sort in Discover, Password/Quick Connect when signing in to Jellyfin) are now one and the same control, with the selected side lit in Beacon's amber. Two of them used to render in plain grey, because a Vuetify button group shows its selection in the surface colour unless it is told otherwise
- The Radio page on the phone now lists your stations one per line, the way the phone remote already did, instead of a grid of boxed tiles that only ever fitted one per line there anyway. The station playing is marked, the site each station belongs to reads underneath its name, and editing or deleting one is still a tap away. The desktop keeps its tiles
- Settings has been reorganised visually. Each section is now a panel of its own instead of loose paragraphs sharing a margin, every setting inside one is separated by a thin line, and explanatory text is consistently quieter than the setting it belongs to, so a section can be taken in at a glance. Nothing moved between sections and no setting changed what it does. On a phone the panels tighten up and the account row wraps instead of squeezing
- The Songs tab on the phone is now Library, with a Songs/Albums switch above the search box: the same list and the same search, pointed at whichever of the two you pick. Tapping an album plays it in its own track order. Both the mobile web view and the phone remote get this, and an old "Songs" link or bookmark still lands in the right place
- On Home, clicking the artwork of whatever is playing opens the Now Playing screen, the same shortcut the player bar's artwork already offers. When nothing is playing and Home is showing your most recent album instead, clicking it still starts that album, as before
- Settings that stay on a device are now kept separately per account. Two accounts sharing one computer or browser no longer see each other's audio quality, saved queue, cached library or dismissed update notice - each starts from its own. Whatever is set today is carried over to the account that's logged in the first time you run this version
- On the phone remote, an action now waits until Beacon has actually carried it out. The action sheet keeps its spinner and stays disabled until then rather than closing immediately, and a short message appears if something didn't get through. Previously a tap that hadn't landed yet looked exactly like one that had, which made it easy to add the same song to the queue twice
- The log level under Settings' Advanced section is now only offered to accounts that are also allowed to trigger a library scan, the same rule the scan button itself already followed
- While casting to an AirPlay device, the song position Beacon works with now follows how much of the song it has actually handed over, instead of assuming the same fixed delay for every track. It stays an approximation either way, since AirPlay speakers never report where they are in a song, unlike Sonos, Chromecast and DLNA speakers, which do and which Beacon goes by
- The cast panel's "Rescan" button now shows a spinner and stays unavailable until the search for speakers has finished, in place of the separate progress bar it used to show. The phone's own device sheet gained the same button, which it never had. And the first search after signing in, which takes a few seconds, now says so instead of showing "No devices found" until it's done
- A radio station's logo is now picked by what the image file actually measures rather than by what the station's page claims about it, and Beacon keeps looking for a larger one when the first it finds is too small for where it's about to be shown. A station whose logo only came back as a 32px browser icon now shows a sharp one behind the Now Playing artwork wherever the station's site offers a bigger version
- Radio station logos are now remembered by the Beacon server across restarts instead of only for as long as it happens to be running. Finding one means fetching the station's own website and reading it, per station - and the desktop app starts its own Beacon with every launch, so until now every launch did that again for every station in your list. They now appear immediately, and the stations' websites are left alone for a week at a time.
- Beacon's copy of your library (the album, artist, playlist and song lists) is no longer kept in a place with a roughly 5 MB ceiling. A large library ran past that, and the whole copy was then silently dropped - which meant Beacon re-fetched the entire catalog from the music server on every single start. That hit Jellyfin hardest, where a full catalog scan takes minutes. Whatever is already stored is carried over on first launch, so nothing has to be fetched again for the sake of the move
- On Jellyfin, a library Beacon already has is now trusted for a day rather than an hour before it quietly refreshes in the background. Re-scanning a large Jellyfin library is a matter of minutes, and doing it hourly competed with whatever you were actually doing. Nothing changes for Navidrome and other Subsonic servers, where that refresh is cheap, and the manual rescan in Settings still updates everything immediately either way
- The album grid fills in noticeably faster on a large library. Beacon asks the music server for several pages of albums at once now, instead of waiting for each one before asking for the next; the first screenful still appears exactly as quickly as before, the rest simply catches up sooner
- The track and artist shown in the player bar now use the full width available to them rather than a fixed narrow column, so longer titles are cut off later. It shows most on internet radio, where the station sends artist and track as a single line of text with nothing to split it across
- The sidebar is now opened and closed with a button at its top, instead of unfolding whenever the mouse happened to pass over it. Whichever way you leave it is remembered per device, so it stays open if you want the labels up all the time. It also takes a little less width when open than it used to
- The speaker picker on the phone (both the remote and the mobile web UI) now reads as one list of places the sound can go, with the current one ticked, instead of a list with two differently coloured rows at the top that did the same thing. "This device" is one of those places rather than a second stop button, and stopping everything sits next to Done with the other actions. A speaker's volume slider is now visibly attached to the speaker it belongs to
- Various small UI sizing/spacing tweaks (the column headings above every track list now read as labels rather than as a greyer first row, and the column the list is sorted by is lit rather than marked only by a small arrow; the Albums grid now spaces its covers the same as the album shelves everywhere else, instead of slightly tighter; the playlist and radio-station tiles are bigger, with room for longer names and artwork worth looking at; every dialog that can hold a lot - the station search, the privacy sheet, the release notes, the keyboard shortcuts - now opens at the same height and keeps the app visible behind it, instead of each one growing to a size of its own, and scrolls inside that rather than cutting its last lines off). The grey placeholders shown while a view loads now match the content that replaces them, in size as well as in number: they fill the width of the window instead of stopping after a fixed few, and nothing shifts as the real covers and rows arrive. The lyrics panel no longer draws placeholder lines while it looks for a text - it says that it is looking, in the drawer and in the fullscreen view alike, so a song that turns out to have no lyrics no longer shows a page of pretend ones first
- While playing an internet radio station, the seek bar is replaced by a small "on air" indicator and how long you have been listening, instead of a progress bar with no real position or length to show. The indicator pulses only while sound is actually coming out, dims when you pause, and stays away entirely until a station has been started, so a station still selected from last time does not announce itself as on air before you press play; it holds still if your system is set to reduce motion. While a speaker is filling its startup buffer, or this device is reconnecting after a dropped connection, the row says so rather than showing a time that would sit frozen or jump around. The desktop, the phone and the phone remote all show the same thing
- While an internet radio station is playing, the controls that only make sense for a queue - shuffle, repeat, previous and next - are now greyed out instead of looking pressable and then doing nothing, on the desktop, in the mobile web view and on the phone remote alike. The skip buttons are also dropped from the lock screen/media widget for as long as the station plays, leaving play/pause
- Starting an internet radio station no longer throws the queue away. Whatever was lined up stays exactly where it was and is still there in the queue view while the station plays, and clicking a song in it picks the queue back up at that song and ends the station. It survives closing and reopening Beacon too, the same way the station itself already did
- Cover art in library grids and lists, artist photos, and radio station logos on the Radio page are now fetched in combined batches - one request per screen instead of one per image - so a large view fills in far fewer round trips, and a self-hosted deployment sitting behind a security proxy produces far less request traffic to look suspicious in the first place (same motivation as the ban fix below). Artwork that has already been fetched is kept - in the open app, on your Beacon server, and in the browser's own storage - so moving back and forth between views shows it instantly instead of loading it again, a second device is answered without going back to the music server at all, and in the browser version the artwork you have already seen is still there after a reload or the next time you open the page. A cover you replace on the music server still appears right away rather than waiting for anything to expire, because Beacon now tells covers apart by which picture they actually are - on Jellyfin and Plex too, where a replaced image used to look identical to the old one from the outside. Artist photos in particular used to be fetched from wherever the music server pointed to, once per artist and once per view; they now come the same way as everything else, which is also what stops them from being re-downloaded on every visit. Artwork is also requested at four fixed resolutions instead of at each place's exact pixel size, so the same cover is stored once for a whole group of views rather than separately for each, which both makes the caches go much further and leaves the music server far less scaling to do - small thumbnails come out sharper on high-resolution displays as a side effect. In the Docker version, how much memory the server may use for this is adjustable with `COVER_CACHE_MB` (see the README), 128 MB by default
- Chromecast and DLNA speakers now report their own volume changes instead of being asked every few seconds, the way Sonos already did. Turning the dial on the speaker, on a TV remote or in another app shows up in Beacon straight away rather than at the next check, and a device being cast to is no longer asked about its volume at all while it is reporting by itself. A DLNA renderer that doesn't support this simply keeps being asked, and Beacon now decides that per device rather than assuming it from the kind of device
- Beacon now stops its background checks (each speaker's volume, the device list, a radio station's "now playing" tag) while the window is hidden, and pauses them entirely for a while when a security proxy in front of a self-hosted Beacon starts refusing requests, waiting longer each time it is refused again. Anything you actually click still goes through and still reports what happened. Previously those checks carried on regardless, which could achieve nothing but keep a block alive that would otherwise have expired
- Lyrics are now remembered by the Beacon server as well as by each device, so a song someone has already looked up costs nothing the second time - on another device, after a reload, or after a restart. That also means far less of your listening leaves your server: a lookup sends the song's title, artist, album and length to the lyrics providers, and it is now made once instead of once per device. A provider that cannot be reached is reported as such rather than recorded as "this song has no lyrics", so a brief outage no longer leaves songs looking empty for a day afterwards. On the device side the cache moved out of the browser's small shared storage, where it grew without limit and could crowd out the saved library and queue

### Removed

- The Autoplay setting for how many songs get added per top-up is gone; it is ten, always. It asked you to pick a number before you could possibly have an opinion about it, which is the kind of question Beacon would rather answer itself. Turning Autoplay on and off is unchanged, and still lives next to Queue in the player bar

### Fixed

- Fixed a cast track sometimes never finishing: it played to its end, but the app went on showing it as playing, the position kept climbing past the end and the visualizer stayed frozen on its last moment. Starting the same track twice in quick succession was enough to trigger it - most likely to be noticed with Autoplay off, since otherwise the next track simply took over. Beacon now ignores the duplicate start, and recognises a track whose end went unreported instead of staying in that state indefinitely
- Fixed dragging a track to a new position in the queue on the phone also starting to play it
- Fixed the phone remote zooming in on the page whenever you tapped its search box, leaving the layout at the wrong scale until you pinched back out. The page is laid out for a phone, so there was nothing to zoom in on
- Fixed the track and station labels in the player bar inviting a click that leads nowhere. While an internet radio station is playing neither line has a page of its own to open, so both are plain text now; the artwork beside them still opens the Now Playing screen, and a song's artist name is still a link. With nothing playing at all, the whole area no longer shows a clickable cursor either
- Fixed internet radio stations showing a generic placeholder instead of their logo on the phone remote. Every logo the phone asked for was being refused by Beacon's own backend, and stations added straight from the discover search, which carry a logo but no website to look one up on, had nothing sent to them in the first place
- Settings no longer offers the keyboard shortcuts list on a phone, where there is no keyboard to use any of them with. It is unchanged on the desktop, where the "?" key still opens the same list. In German it is now called "Tastenbelegungen"
- The Now Playing screen on a phone now uses the space it has. The cover was sized well below what fits - on a typical phone it filled about two thirds of the width available to it, with half the height of the screen left empty - and because the lyrics and the radio title log are shown by flipping that same card over, they were small for the same reason. All three are now close to as large as the screen allows, in portrait and landscape. The buttons that used to float in the corner of the cover moved up into the bar at the top of the screen, which grew a little to hold them comfortably
- Fixed the Sign out button in Settings sitting awkwardly on a phone, on a line of its own under the username with the language setting right underneath, so it looked like a third line of account text rather than a button. The account row now stays on one line at every width, exactly as on the desktop, with the server address shortened with an ellipsis when there is not enough room for it. The account block is also closed off from the setting below it by the same hairline every other block in that panel already had - on the desktop too, where the two used to share an edge
- Fixed AirPlay speakers being listed as needing to be paired first when they need nothing of the kind. Beacon decided this from whether a device speaks AirPlay 2 at all, which every current receiver does - including an Apple TV set up without a password, and AirPort Express units. On the phone and the phone remote those devices were greyed out with "Needs pairing in the Beacon app first" and could not be picked at all. Beacon now asks the device whether the connection it actually streams over wants pairing, so only the speakers that really do are marked - a speaker you have put a password on still counts, and pairing it once is what clears that too
- Fixed "Clear cache" in Settings leaving most of the cache behind. It cleared the saved library and lyrics but not cover art, artist photos or radio station logos - and artwork is by a wide margin the largest of them, so the button was clearing almost nothing of what anyone means by it. It now clears all of them, and reports success once they are actually gone rather than the moment it starts, which on a large library is a visible difference and could previously leave a wipe half-done if the app was reloaded right after
- Fixed the phone remote keeping an old version of itself after Beacon was updated. Its files carry no version in their names, and without being told otherwise a phone browser decides for itself how long to trust what it already has - often most of a day - so a changed layout simply did not arrive, and reloading could not help because nothing was being asked for. The phone now checks every time and is told "unchanged" in a single small reply when nothing has moved, so this costs no extra loading. If your phone is still showing an old version after this update, clear the site data for Beacon once (or remove and re-add it from your home screen) - that last stale copy is the one it was never going to ask about
- Fixed a radio station whose logo is a vector image being shown in a framed box, as if it were a square cover, while stations with an ordinary transparent logo floated free as intended. Beacon could not read a vector image to tell whether it had a transparent background and fell back on assuming it did not; it now treats one as transparent, which is what a logo drawn as lines and shapes on nothing actually is. Affects the Now Playing screen, where the framing shows most
- Fixed many internet radio stations showing no logo at all once they had been added to your list, even where the discover search had just shown one for that same station. Two separate things kept Beacon from finding it. Where a station's website forwards you on to a different address, as 1LIVE's einslive.de does, the logo was looked for at the address Beacon started from rather than the one it ended up on. And where a site puts a lot of styling into the top of its page ahead of the logo, as hitradion1.de does, Beacon stopped reading before it ever got there; it now reads to the end of that section however long it is, and no further. Those stations show their logo again everywhere, in the list, the player bar and the Now Playing screen alike. A station that has been showing none can take a few hours to catch up, since Beacon remembers a fruitless search for a while before trying again
- Fixed the lyrics drawer coming up empty the first time it was opened after starting Beacon, claiming the song had no lyrics until the Now Playing screen was visited once. It now looks them up as it opens, and while it is looking it says so instead of reporting that there are none
- Fixed picking a speaker another Beacon session is using going wrong in three separate ways. Switching to one stopped the speaker you were already listening on and dropped the music back to this device before you had even answered the "take it over?" question, and answering it then did nothing at all. "Take over" on a speaker you wanted to add stopped every other speaker you had playing. And picking one from the phone remote did nothing, while a confirmation nobody was looking at appeared over on the desktop instead. The speaker you are on now keeps playing until you answer, confirming carries out the whole switch, taking a speaker over adds it to the ones you are already on, and the phone takes it over directly
- Fixed picking a speaker while playback is paused making a sound. Adding a second speaker, or switching to one, while already casting started the music playing outright; and picking a first one, which did correctly stay paused (see 0.1.4), still made the speaker play a moment of the song before being stopped again. A speaker picked while paused is now simply reserved: it is yours, it holds the song and where you are in it, and it stays silent until you press play. This applies wherever the choice is made - the desktop panel, the phone's sheet and the phone remote. Radio is the one exception and still makes that brief sound, because whether a station plays on a given speaker at all is only found out by trying it
- Fixed moving a cast from one speaker to another. Switching between two Sonos speakers interrupted a third Sonos that was playing on its own and had nothing to do with the switch; the switch itself locked up the play/pause and seek controls for several seconds while it looked for the speaker on the network; and afterwards the queue stalled, with the song finishing normally and then the speaker staying silent for roughly the length of another track before the next one started on its own. Only speakers actually grouped behind the one being switched off are restarted now, the speaker is looked up the same fast way as everywhere else in Beacon, and position tracking is handed over to the speaker that keeps playing
- Fixed a speaker that refuses to stop being left listed as still playing with nothing said about it, so the panel kept showing it as a target that Beacon no longer had. The failure is now reported and the speaker drops out of the list
- Fixed both device pickers showing a set of speakers that was not real. The phone's sheet kept whatever it showed when it opened and applied that as your choice on "Done", even after the speakers had changed underneath it, and the desktop panel's tick marks briefly flicked back to the speaker just switched away from right after applying a change. "Done" on the phone now also reports a failure rather than appearing to do nothing, and stays open so the selection can be tried again
- Fixed casting to some Chromecast devices (e.g. a Google TV) staying completely silent, with no error shown anywhere. Those devices can keep their own app running instead of switching to the one that actually plays what's sent to it, and were accepting the request without ever starting playback. Beacon now explicitly switches the device into playback mode first
- Fixed a failed cast reporting the speaker's raw technical fault ("UPnP Error 800 received: from 10.2.2.112") as the whole error message. The cast panel now says which speaker it was and what went wrong - it refused what it was sent, it was busy, or it could not be reached - with the original text kept underneath in smaller type
- Fixed the stream-info panel (in the cast device picker) claiming a cast radio station was being transcoded to MP3, regardless of the audio quality chosen for casting. - Added a Trace log level, one step past Debug - Debug now covers Beacon's own backend code only, Trace also turns on the third-party libraries underneath it (Sonos/AirPlay, HTTP clients) for full SOAP/HTTP-level detail when actually troubleshooting one of those. A new `LOG_LEVEL` environment variable sets the starting level the same way the Settings dropdown does, for a deployment that never comes up far enough to reach Settings
- Added links to Spotify, Apple Music, TIDAL, YouTube, Deezer, Discogs, and MusicBrainz on artist pages, and on the Home "New to explore" shelf - the shelf previously only linked out to Deezer itself (or MusicBrainz as a fallback), and an artist page for someone already in your library had no external links at all

### Changed

- Changed the Electron Remote Control PWA's look to match the mobile web UI - same amber/navy color palette, lighthouse app bar, tab bar icons/labels, Now Playing layout (single row of transport controls, filled play button, cast toggle next to the volume slider), and themed seek/volume sliders instead of its own separate blue-accented style with plain browser-default sliders
- Changed the lyrics view's "pick a different match" list on mobile from a dropdown menu to a full-width sheet - easier to hit and to read than a small floating panel anchored to a toolbar button
- Various small UI sizing/spacing tweaks (mobile web UI, Now Playing on wide monitors, lyrics on mobile) based on actually using it

### Fixed

- Fixed the app log file (see 0.1.3) tagging every line from the backend as an error, even completely normal status messages - the backend logs everything to the same output stream regardless of severity, same as most command-line programs, and the log file was mistaking that stream choice for severity
- Fixed queue changes made while casting (reordering, adding, removing, shuffling) not being followed by auto-advance once nothing was around to manually skip to the next song - the cast target kept auto-advancing through whatever queue order was active when the current song started, ignoring anything changed since
- Fixed picking a cast target while local playback was paused starting playback on that device right away instead of staying paused
- Fixed the Previous/Next buttons resuming playback immediately even if it was paused - navigating now stays paused, matching what selecting a cast target already did
- Fixed the "now playing" display occasionally showing a different song than what was actually playing when two devices controlled the same cast session and both changed something around the same time
- Fixed shuffle not actually shuffling the first song when playing a whole playlist/album from the top - it always started on track 1 in its original order, with shuffle only kicking in from the second song onward
- Fixed the mobile web view carrying over a tab's scroll position into whichever tab you switched to next, instead of each tab keeping (and restoring) its own
- Fixed the Docker/web deployment's audio stream to cast devices being vulnerable to nginx buffering it all at once instead of forwarding it continuously in real time - could turn a brief network hiccup mid-song into a multi-minute stall stuck at 0:00 instead of recovering
- Fixed synced lyrics opened mid-song showing the very first line instead of scrolling straight to wherever playback actually is - it caught up on its own once the next line's timestamp passed, but sat at the wrong spot until then
- Fixed dragging a track to swap it with the very next one in the queue landing it one position further than intended - the drop target only accounted for which row you dropped on, not which half of it, so a drag moving down past a row's own boundary silently pulled in the row after it too
- Fixed pressing Play again after a cast session's queue finished playing (no repeat, last song ended): position stayed frozen at 0:00 and the audio visualizer/synced lyrics never got going, since resuming just asked the already-finished stream to continue instead of properly restarting it - the same bug fixed for local playback in 0.1.1, which never covered casting
- Fixed the Home "Discover" shelf's Reroll button rarely changing anything - which artists its suggestions were seeded from was picked the same way every time (always your top few most-played, in the same order) rather than varying, so a reroll usually landed right back on the same result; suggestions also now refresh daily instead of monthly
- Fixed a temporary MusicBrainz outage or rate-limit response permanently blanking out an artist's info (recommendations, external links) instead of just that one attempt - a failed lookup was being cached the exact same way as a genuine "nothing found" result, so it never got retried later once MusicBrainz recovered

### Removed

- Removed the `DEBUG` environment variable - it only ever gated the API docs at `/api/docs` (unauthenticated by design, not something a real deployment needs reachable) and, separately, some backend developer-testing toggles; log verbosity now has its own `LOG_LEVEL` variable instead (see Added)

### Security

- Updated Electron from 38 to 39, closing out a batch of upstream security advisories Dependabot flagged (context isolation, protocol handling, and related renderer-process issues)

- Fixed the casting device's startup-buffering calibration sometimes never completing (falling back to a rough guess for the whole track, throwing off lyrics sync and auto-advance timing) - a device legitimately reporting position 0 right at track start was being treated the same as no reading at all and skipped
